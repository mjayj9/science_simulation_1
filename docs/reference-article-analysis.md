### 반드시 분리하는 조건

- A의 선형 높이 경향은 같은 footprint와 각 높이별 bounding-volume 안에서 다시 최적화한 open-box/funnel 계열 결과다. 이를 단순 구·원기둥의 높이 보정으로 사용하지 않는다.
- B의 2–20배는 사례별 높이·PV 면적·위도·계절·반사판·평면 기준 자세가 다르다. 특히 “1.5–4배”는 **태양전지 면적/생성 에너지**의 불리함이며, 3D 구조의 단순 활성면적 배율이 아니다.
- C의 근접 흰 종이는 finite diffuse background이며 일반적인 무한 지면 albedo가 아니다. aluminium paper는 specular이고 aluminium cup은 45° 측면을 가진 concentrator다. 컵 이득을 구의 순수 형상 이득으로 합치지 않는다.
- D의 sphere support footprint 0.01 m²와 horizontal projection 약 0.07 m²는 다른 토지 지표다. 공식 공정 비교의 swept projection에는 지름 0.3 m에서 유도한 `π(0.15 m)² = 0.0706858 m²`를 사용해야 하며, pole 면적으로 형상 전체 토지점유를 축소하지 않는다.
- A–D 모두 현재 source-equivalent 실행 결과가 없으므로 방향 판정은 `미평가`다. 숫자가 비슷해 보여도 `경향 일치`, `부분 일치`, `불일치` 중 하나로 승격하지 않는다. 실제 실행 뒤에만 동일 분모로 정량 오차를 산출하고 신뢰등급을 매긴다.

## 참고 기사: 태양광 발전에 영향을 미치는 6가지 요소

## 1. 목적과 사용 경계

이 문서는 첨부된 HTML 기사에서 제시한 여섯 가지 정성 요소를 시뮬레이터의 입력, 계산 단계, 손실 장부(loss ledger), 한국어 UI에 연결한다. 이 기사는 **요소 누락을 점검하는 정성적 체크리스트로만 사용**한다. 기사에는 공학 공식, 계수, 단위가 붙은 데이터, 실험 조건, 참고문헌이 없으므로 다음 용도로 사용하지 않는다.

- 기본 계수나 허용 범위의 근거
- 지역별 일사량 또는 발전량 데이터
- 온도·구름·비·안개·오염의 감쇠율
- 최적 경사각·방위각
- 모듈 또는 시스템 성능 검증값
- 제조사 제품의 성능·품질 근거

따라서 기사에서 가져오는 것은 `일사 강도`, `모듈 효율`, `기후`, `작동 온도`, `오염도`, `설치 각도·방향`이라는 **분류와 제한적인 정성 방향성**뿐이다. 실제 공식, 계수, 기본값, 검증 허용오차는 공식 기술문서와 데이터시트에 근거해 별도로 결정하며 `docs/modeling-research.md`에 기록해야 한다.

| 오염도(청결도) | `soilingLossFraction` 또는 시간별 오염 투과율, 출처, 마지막 청소 시각. 비율은 내부에서 0–1, UI에서 `%` | 패널별 유효 일사량 또는 광전류에 정확히 한 번 반영. 적용 위치는 선택 모델과 함께 문서화 | `오염 손실`을 오염 전·후의 W/Wh 차이로 표시. 전사 일사량과 전기 출력 양쪽에 중복 적용 금지 | `오염 손실률`, `청소 전/후`, `입력 출처: 수동/측정/시나리오`, 패널별 상태 | 먼지·오물이 입사광과 발전에 영향을 줄 수 있다는 방향성만 채택. 계절률·청소 주기·비 세척 효과는 미채택 |
| 설치 각도·방향 | 패널별 위치, 전면 법선, 경사각, 방위각. 파생: 태양 벡터, 입사각(AOI), 전면/후면 판정, IAM | 직달 코사인 투영, IAM, 산란광·지면반사 전사, 하늘 가시율과 음영 계산 | `코사인/배향 영향`, `IAM`, `음영`을 정의된 기준 사례와 비교해 구분. 이미 POA에 반영한 각도를 임의의 `설치 손실률`로 다시 차감하지 않는다 | 3D 법선 화살표, `경사각/방위각`, `태양 고도/방위`, `입사각`, `직달/산란/반사`, 전면/후면 경고 | 각도와 방향이 수광량에 중요하다는 관계만 채택. 보편적인 최적값은 미채택 |

### 각도 표기 계약

UI와 저장 파일은 방위각 기준을 반드시 표시한다. 권장 표기는 `0° = 북, 90° = 동, 180° = 남, 시계방향 증가`이고, 경사각은 `0° = 전면이 하늘을 향하는 수평 패널, 90° = 수직 패널`이다. 3D 엔진 내부에서는 패널 전면 법선 벡터를 기준 상태로 삼고 경사각·방위각은 사람이 읽기 위한 파생값으로 취급한다. 기사의 “각도와 방향” 문장은 이 좌표 규약을 제공하지 않는다.

## 4. 중복 차감을 막는 계산·손실 장부

여섯 요소는 서로 독립인 여섯 개의 백분율 손실이 아니다. 특히 `일사 강도`와 `기후`, `모듈 효율`과 `온도`, `설치 각도`와 `패널면 일사량`은 같은 계산 사슬의 서로 다른 입력·상태·단계다. 권장 추적 순서는 다음과 같다.

1. **기상 자원**: 시간별 GHI/DNI/DHI, 기온, 풍속과 출처
2. **기하·광학**: 태양 위치, 패널 법선, 직달 코사인 투영, 산란·지면반사 전사, 하늘 가시율, 장애물·자기 음영, IAM
3. **오염 후 유효 복사량**: 오염을 한 번 반영한 전기적 유효 일사량
4. **열 상태**: 선택한 열 모델 정의에 맞춘 모듈/셀 온도
5. **모듈 DC**: 간단 효율식 또는 온도 의존 단일 다이오드 모델 중 하나
6. **회로·인버터**: 불일치, 바이패스, 배선, MPPT, 인버터와 클리핑

손실 워터폴은 각 단계 전·후의 **전력 또는 에너지 차이(W/Wh)**를 우선 저장해야 한다. 백분율에는 분모를 함께 표시한다. 상호작용이 있는 항목은 적용 순서에 따라 배분값이 달라질 수 있으므로 UI에 고정된 계산 순서와 비교 기준을 공개한다.

다음 규칙은 필수다.

- API나 파일의 GHI/DNI/DHI가 실제 기상 상태를 이미 나타내면 구름·비·안개 프리셋 승수를 추가로 곱하지 않는다.
- `기후` 자체를 하나의 범용 손실률로 만들지 않는다. 맑은 하늘과 실제 기상의 차이를 보여줄 경우에도 장치 손실과 분리된 **자원 비교**로 표시한다.
- 정밀 모드에서는 단일 다이오드 모델이 변환과 온도 효과를 만든다. 그 결과에 기준 효율 또는 온도 손실률을 다시 곱하지 않는다.
- 패널 방향과 IAM이 POA 계산에 반영됐으면 별도 설치 감쇠율을 다시 적용하지 않는다.
- 오염은 광학 단계 또는 광전류 단계 중 구현이 선택한 한 곳에만 적용한다.
- 음영, 오염, 불일치, 바이패스 동작은 서로 다른 물리 단계이지만 상호작용한다. 회로 해석에 이미 포함된 불일치·바이패스 효과를 워터폴에서 다시 감산하지 않는다.
- 비가 온다는 이유만으로 자동 세척률을 부여하지 않는다. 명시적이고 검증된 세척 모델이나 사용자 시나리오가 있을 때만 상태를 변경한다.
- 지평선 아래의 태양, 패널 후면 직달광, 음수 일사 입력은 기사와 무관하게 물리·입력 검증 규칙으로 0 처리하거나 오류로 알린다.

## 5. 원문 주장 감사와 신뢰 경계

판정은 `정성 채택`, `조건부`, `별도 검증`, `배제`로 구분한다. `정성 채택`도 수치 계수를 승인한다는 뜻은 아니다.

| 원문 요지 | 판정 | 과장·오해 가능성 | 앱에서의 처리 |
|---|---|---|---|
| 빛이 강할수록 모듈이 더 많은 전기를 생산한다 | 조건부 정성 채택 | 보통의 동작 범위에서는 방향성이 유용하지만 저일사 비선형성, 온도 상승, 포화, 인버터 클리핑을 생략한다 | 일사 입력과 실제 전기 모델로 계산. 선형 범용식으로 단정하지 않음 |
| 중국 서북부·북부처럼 자원이 풍부한 지역은 “발전 효율”이 더 높다 | 배제·별도 검증 | 일사 자원 또는 에너지 수율과 모듈 변환 효율을 혼동한다. 지역 일반화이며 기간·데이터셋도 없다 | 지역 우열이나 효율 기본값으로 사용하지 않음. 위치·기간별 공식 기상 데이터로만 비교 |
| 고효율 모듈은 동일한 조명에서 더 많은 전력을 생산한다 | 조건부 정성 채택 | 같은 면적, 스펙 정의, 온도, 스펙트럼, 열화 상태 등 비교 조건이 빠져 있다 | 면적당 결과와 모듈 수 기준 결과를 함께 표시하고 모델별 데이터시트를 사용 |
| 비·안개에는 일사와 발전이 줄고 맑은 날에는 증가한다 | 조건부 정성 채택 | 비 자체와 구름의 효과를 분리하지 않으며 산란광, 냉각, 오염 세척, 시간 변화를 누락한다 | 실제/추정 GHI·DNI·DHI와 기온·풍속을 사용. 날씨명에 고정 감쇠율을 부여하지 않음 |
| 일정 범위에서는 온도 상승이 효율을 높이고 지나치게 높을 때 저하된다 | 배제·우선 검증 | 기술 종류와 기준 조건이 없다. 일반적인 태양광 모듈에 보편 법칙처럼 적용하면 온도 효과의 부호를 잘못 만들 위험이 크다 | 기사 문장을 공식이나 기본 곡선으로 구현하지 않음. 모듈별 온도계수와 검증된 열·전기 모델을 사용 |
| 먼지·오물은 햇빛 흡수를 방해하므로 정기 청소가 중요하다 | 조건부 정성 채택 | 손실률은 입자 종류·퇴적·강우·경사·지역에 따라 다르고, 최적 청소 주기는 안전·비용·수자원까지 포함한 별도 문제다 | 사용자/측정 기반 오염률을 적용. 기사에서 계절 손실률이나 청소 주기를 추출하지 않음 |
| 합리적인 설치 각도와 방향은 하루 동안 수광량을 늘린다 | 조건부 정성 채택 | 최적값은 위도만이 아니라 계절, 지평선, 산란비, 알베도, 음영, 사용시간대, 추적 여부와 목적함수에 좌우된다 | 패널별 법선과 시간 적분으로 비교. 보편적인 최적 경사각·방위각을 하드코딩하지 않음 |
| 발행사가 업계 최고이며 고품질 제품을 제공한다 | 배제 | 시험 성적이나 독립 검증이 없는 마케팅 주장 | 계산, UI 추천, 문서의 성능 근거로 사용하지 않음 |

### 온도 서술에 대한 특별 주의

기사의 온도 문장은 여섯 항목 중 구현 오류를 일으킬 위험이 가장 크다. 앱은 온도가 상승하면 무조건 효율이 먼저 좋아지는 구간을 만들면 안 된다. 모듈 기술별 데이터시트의 전압·전류·전력 온도계수, 선택한 열 모델의 적용 범위, 기준 온도를 확인한 뒤 I–V 상태를 계산해야 한다. 온도 기여분은 기준 사례에 비해 이득 또는 손실이 될 수 있는 **부호 있는 결과**로 표시한다.

## 6. 공학 근거의 별도 검증 경로

아래 자료는 첨부 기사와 분리된 검증 경로다. 링크가 공식 기관 또는 서비스의 기술 문서라는 사실과, 특정 공식·버전·계수가 현재 앱의 조건에 적합하다는 판단은 별개다. 실제로 채택한 모델의 버전, 공식, 변수, 단위, 범위, 기본값, 단순화와 검증 결과는 `docs/modeling-research.md`에 남긴다.

| 검증 대상 | 우선 확인할 1차·공식 기술 출처 | 기사로 대신할 수 없는 내용 |
|---|---|---|
| 태양 위치 | [NREL Solar Position Algorithm](https://midcdmz.nrel.gov/spa/) | 시간척도, 방위각 규약, 굴절, 기준 사례와 수치 오차 |
| 일사 성분·POA·IAM·열·PV·인버터 모델 | [Sandia PV Performance Modeling Collaborative](https://pvpmc.sandia.gov/modeling-guide/) | 전사식, IAM, 모델 계수의 정의·단위·적용 범위 |
| 간단 발전 모델·교차 검증 | [NREL PVWatts V8](https://pvwatts.nrel.gov/version_8.php) | 손실 정의, 기준 조건, 온도·인버터 처리와 벤치마크 |
| TMY·월간·연간 일사와 발전 자료 | [JRC PVGIS 비대화형 API](https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/using-pvgis-5/api-non-interactive-service_en) | 데이터셋, 공간·시간 해상도, 기간, 요청 파라미터와 제한 |
| 장기 기상자료 교차 확인 | [NASA POWER API](https://power.larc.nasa.gov/docs/services/api/) | 변수 정의, 단위, 시간 기준, 격자·재분석 특성과 결측 처리 |
| 현재·예보·과거 시간별 기상 | [Open-Meteo API 문서](https://open-meteo.com/en/docs/) | 변수·모델·시간대·조회 시각과 API 응답 해석 |
| 모듈 효율·전기·온도계수 | 대상 모듈 제조사의 최신 데이터시트와 해당 시험 성적/적용 표준 | 기술별 `Pmax/Voc/Isc/Vmp/Imp`, 온도계수, 허용오차와 시험 조건 |
| 오염·세척 | 현장 계측, 유지보수 기록, 적용 지역·기후에 맞는 검증 논문 또는 공식 기술보고서 | 오염률의 시간 변화, 강우 세척, 경사 의존성, 청소 기준 |

Open-Meteo 같은 서비스 문서는 API 변수와 응답의 공식 설명에는 적합하지만, 데이터의 물리적 정확도는 사용된 모델·지역·시간에 대해 PVGIS, NASA POWER, 관측 또는 다른 검증 자료와 교차 확인해야 한다. 제조사 데이터도 정확한 모듈 모델, 시험 조건, 문서 버전을 함께 저장해야 한다.

## 7. UI의 출처·확실성 표시 요구

`공식·근거` 화면과 패널 추적 화면은 각 값에 다음 메타데이터를 붙여야 한다.

- 값의 역할: `사용자 입력`, `API/파일 입력`, `모델 추정`, `파생 계산`
- 단위와 좌표·방위각 규약
- 데이터 제공자, 데이터셋/모델명과 버전(가능한 경우)
- 대상 위치, 유효 시각, 조회 시각, 시간·공간 해상도
- 사용 공식과 계수의 출처 링크
- 적용 범위, 가정, 단순화, 알려진 한계
- 기사에서 유래한 항목에는 `정성 참고 항목 — 계수 출처 아님` 배지

패널 한 개의 계산 추적에는 최소한 다음 순서를 노출한다.

`기상 일사 → 태양·패널 기하 → 직달/산란/반사 POA → 음영·IAM → 오염 후 유효 일사 → 셀 온도 → I–V/DC → 회로 → 인버터/AC`

기사의 문장을 사용자에게 보여줄 필요가 있다면 요약문과 원문 링크만 제공하고, 공식 또는 현재 입력값의 근거처럼 배치하지 않는다.

## 8. 구현·검토 체크리스트

- [ ] 여섯 요소 모두 입력 또는 파생 상태와 연결되어 있다.
- [ ] 기사에서 수치 기본값이나 감쇠율을 가져온 항목이 없다.
- [ ] 일사량과 기후가 중복 감쇠되지 않는다.
- [ ] 단일 다이오드 결과에 모듈 효율이나 온도 손실을 다시 곱하지 않는다.
- [ ] 오염, 각도/IAM, 음영, 회로 불일치가 각각 정확히 한 번만 적용된다.
- [ ] 온도 결과는 이득/손실 양쪽 부호를 허용하고, 기사 속 온도 상승 주장을 하드코딩하지 않는다.
- [ ] 지역명으로 효율 또는 일사 기본값을 추정하지 않는다.
- [ ] 기상자료와 모델 추정값의 출처·시각·해상도를 UI와 내보내기에 보존한다.
- [ ] 손실률에는 비교 기준과 분모가 표시되고 W/Wh 단계값으로 재현할 수 있다.
- [ ] canonical, 영어 대체 링크, 본문의 상업 링크는 출처 감사용으로 보존되지만 공학 근거로 인용되지 않는다.

## 결론

첨부 기사는 사용자에게 보여줄 여섯 개의 영향 범주를 빠르게 식별하는 데에는 유용하다. 그러나 범주들이 서로 독립 손실이라는 근거도, 이를 수치화할 공식이나 계수도 제공하지 않는다. 앱은 이 여섯 항목을 **자원 입력 → 광학·기하 → 오염 → 열 → 전기 변환**의 계산 사슬에 배치하고, 모든 수치 결정은 별도의 공식 기술 출처와 검증 결과에 근거해야 한다.
